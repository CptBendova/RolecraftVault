# Brand artwork

Everything the app is drawn from, and the scripts that turn it into the files
each platform loads. Kept so the icons can be regenerated rather than being
recoverable only from whatever was last committed to `app/vendor`.

```
crest-1024.png        the mark. Every icon and the lock screen come from this
src/                  original source pictures kept for future branding work
ico-app/, ico-setup/  the sizes that go into each .ico, regenerated by make-ico
```

## Scripts

Run from anywhere; each works out the repo root from its own location.

- `pack-brand.ps1` renders the app icon, setup icon inputs, Android icons and
  splash from `crest-1024.png` and the setup source picture.
- `pad-android-icons.ps1` pads the launcher icons so the crest sits inside the
  adaptive-icon safe zone. Android masks a 108dp icon down to roughly the middle
  72dp, and every launcher masks a different shape.
- `make-ico.js` builds a PNG-in-ICO from a folder of square PNGs. An ICO is a
  small directory followed by the images, and since Vista each may be a PNG
  verbatim.
- `inline-favicon.js` produces the data URI in `web/index.html`. The web bundle
  is dropped into other people's pages, so it cannot reference a file.

## If you change the crest

`app/vendor/crest-1024.png` and `crest-256.png` are what the interface loads, and
they are **not** carried by a `.rcvup` patch — a patch contains `app.js` alone. A
crest change needs a full installer, even though `npm run sign` will report no
shell change. See rule 6 in CLAUDE.md.
